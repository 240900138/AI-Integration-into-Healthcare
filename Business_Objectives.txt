Business Objectives (25 Marks)
Business objectives
The primary objective of HealthCareAI is to develop and apply an end-to-end machine learning solution that cleans and analyses hospital admission records, predicts the medical condition of an admission, and honestly evaluates whether the available data supports that prediction. This reduces manual analysis effort and gives hospital staff clear, trustworthy information about their data.
The goals of HealthCareAI are as follows:
•	Build a reliable data preparation pipeline that cleans 55,500 admission records (name formatting, duplicates, near-duplicates and invalid billing amounts).
•	Explore admissions, billing, age and length of stay so that staff can see patterns in tables and charts.
•	Train and tune a Random Forest classifier to predict the medical condition and compare it with a baseline, Logistic Regression and a Decision Tree.
•	Evaluate the model on unseen patients using accuracy, precision, recall, F1-score, a confusion matrix and cross-validation.
•	Provide a prediction tool (command line and web interface) that returns the predicted condition with the probability of every condition.
•	Prevent data leakage by splitting the data by patient, so that the reported performance can be trusted.
•	Document the limitations, risks and ethical considerations of using AI in healthcare.

Business success criteria
•	The data pipeline is reproducible: the whole system runs in three commands (train.py, test.py, predict.py) and every table and chart is regenerated automatically. Achieved.
•	The model is evaluated on 9,908 unseen admissions using patient-level splitting and grouped 5-fold cross-validation (mean accuracy 16.40% ± 0.39%). Achieved.
•	The model should beat the best baseline (16.45%) by a meaningful margin. The tuned Random Forest scores 16.63% (macro F1 0.1656), only 0.18 percentage points above the baseline and below the chance level of 16.67%. Not achieved – and this is reported transparently.
•	Weighted and macro precision, recall and F1-score are reported for every condition (about 0.15–0.18), together with a confusion matrix and prediction confidence (mean 0.181).
•	A prediction for a single admission is returned almost instantly, and a whole CSV file can be predicted in one run.
•	The solution can be retrained on any CSV with the same columns by running one command (train.py).
•	Results, limitations and risks are documented clearly, so that no one mistakes the prototype for a clinical tool.

Business background
Hospitals generate large volumes of data every day: patient details, admission records, medication, test results and billing information. Analysing this data by hand is slow and error-prone, and healthcare managers need quick insight into who is admitted, why, for how long and at what cost. Artificial intelligence is increasingly used in healthcare for resource planning, triage support and billing analysis.
Healthcare is also a high-stakes industry. An AI system that makes wrong predictions can harm patients, so every model must be tested rigorously against simple baselines before it is trusted. HealthCareAI applies this discipline: it builds the full pipeline, tests it on unseen patients and reports the outcome openly. The dataset used (healthcare_dataset.csv) contains 55,500 admission records; its statistical properties (independent fields, near-uniform distributions and randomly capitalised names) indicate that it is synthetic, which explains the result.
Requirements
•	Dataset: healthcare_dataset.csv – 55,500 hospital admission records with 15 columns: Name, Age, Gender, Blood Type, Medical Condition, Date of Admission, Doctor, Hospital, Insurance Provider, Billing Amount, Room Number, Admission Type, Discharge Date, Medication and Test Results.
•	Generated data files: healthcare_clean.csv (cleaned data, 49,904 rows), train_split.csv (39,996 rows) and test_split.csv (9,908 rows).
•	Python 3 with Pandas, NumPy, Scikit-learn and Joblib (requirements.txt), Matplotlib and Seaborn for charts, and Streamlit for the web interface.
•	A labelled target: Medical Condition (six classes: Arthritis, Asthma, Cancer, Diabetes, Hypertension, Obesity).
•	Evaluation using accuracy, precision, recall, F1-score, a confusion matrix and cross-validation, compared with baseline models.
•	A trained model file (model.pkl): one Scikit-learn pipeline that bundles the one-hot encoder, the StandardScaler and the Random Forest, so no separate scaler or encoder file is needed.

Constraints
•	Dataset limitation: the dataset looks synthetic – billing, condition, medication, test result and admission type are statistically independent (correlations close to 0, and the average bill is about $25,500 for every condition). A model cannot learn a relationship that does not exist in the data.
•	Missing clinical information: real diagnosis needs symptoms, vital signs, laboratory values and clinical history. None of these are in the dataset, so the model only sees administrative fields.
•	Data quality: 534 exact duplicates, 4,966 near-duplicates (same patient, date, condition and bill) and 96 negative billing amounts had to be removed, leaving 49,904 of the 55,500 rows.
•	Repeat patients: the same patient can appear several times; the data is therefore split by patient name so that no patient appears in both the training and the test set.
•	Currency: the dataset does not state a currency; amounts are shown with a dollar sign.
•	Privacy: the dataset contains patient and doctor names. They are not used as model features; real hospital data would require consent and compliance with the Protection of Personal Information Act (POPIA).
•	Update frequency: periodic retraining with updated hospital data would be required to keep any model relevant.
•	Not a replacement: the system supports analysis and decision-making but is not a diagnostic tool and does not replace a doctor.
•	Lack of temporal modelling: the classifier treats each admission independently; time is only used in the monthly trend analysis.
•	Computational: the saved model is small and predicts almost instantly; training with GridSearchCV (12 combinations, 3 grouped folds) takes a few minutes on a standard laptop.

Tools and techniques
Programming Environment
•	Language: Python 3.x
•	IDE: Visual Studio Code
•	Version control: Git and GitHub (for project management)
Core Libraries
•	Pandas and NumPy (data handling)
•	Scikit-learn (machine learning pipeline, GridSearchCV, metrics)
•	Matplotlib and Seaborn (visualisation)
•	Joblib (model persistence)
•	Streamlit (web user interface)
Machine Learning Technique
•	Algorithm: Random Forest Classifier (ensemble method) inside a Scikit-learn Pipeline
•	Preprocessing: ColumnTransformer – OneHotEncoder on six categorical features and StandardScaler on four numeric features (age, billing amount, length of stay, admission month)
•	Hyperparameter tuning: GridSearchCV with grouped 3-fold cross-validation over 12 combinations; best model: 200 trees, maximum depth 10, minimum leaf size 5
•	Comparison models: baseline (most common class), Logistic Regression and Decision Tree
•	Evaluation: accuracy, precision, recall, F1-score, classification report, confusion matrices and grouped 5-fold cross-validation
